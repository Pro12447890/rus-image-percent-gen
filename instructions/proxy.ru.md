# Прокси: инструкция для ИИ (инструмент `proxy_switch`)

Этот файл — инструкция по выбору исходящего прокси. В самом пакете плагина **нет
никакого адреса прокси**: по умолчанию всё идёт напрямую, а адрес задаёт пользователь —
свой (и держит его в конфиге записи, а не в коде плагина).

## Зачем это нужно

Модели вроде Gemini (`google`) недоступны из некоторых стран. Тогда весь процесс DSH
надо пустить через прокси пользователя — вместе с моделями, поиском и HTTP-MCP.

## Действия

| `action` | Что делает |
|---|---|
| `status` | текущий маршрут: режим, адрес (логин скрыт), список обхода, кандидаты, результат последней проверки, доступен ли `undici`, что в переменных окружения |
| `check` | **проверка по пингу**: по очереди идёт через каждый кандидат настоящим запросом и показывает время ответа, внешний IP и **страну**; `"choose": true` — сразу переключиться на быстрейший из ответивших |
| `set` | включает свой прокси — **по частям** (`host`, `port`, `user`, `password`, `protocol`) или одной строкой `proxy` |
| `env` | берёт адрес из переменных окружения (`HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`) |
| `off` | возвращает прямой выход |
| `help` | отдаёт этот текст (`lang: "ru"` или `"en"`) |

Дополнительные поля:

- `targets: [{ name, protocol, host, port, user, password }]` — что проверять в `check`,
  **у каждого прокси свои части**. Приоритетнее `proxies`.
- `proxies: ["http://…", "http://…"]` — то же готовыми строками. Без обоих берутся
  кандидаты из конфига записи (`proxy.candidates`), а если и их нет — текущий адрес.
- `choose: true` — после проверки включить быстрейший ответивший адрес.
- `timeout_ms` — сколько ждать каждый прокси (по умолчанию 5000 мс).
- `probe_url` — крошечная страница, которую тянем через прокси для проверки (по умолчанию
  сервис, отдающий внешний IP и страну; если он не ответит — берётся второй из цепочки).
- `noProxy: ["localhost", "api.example.com"]` — что ходит напрямую. По умолчанию
  только локальные адреса.
- `export_env: false` — не отдавать переменные прокси дочерним процессам
  (`curl`/`git` в терминале, stdio-MCP). По умолчанию отдаются.

## Ввод адреса по частям

У каждого прокси свои хост, порт, логин и пароль, поэтому ввод раздельный — не нужно
собирать строку вручную и путаться с кодированием пароля:

```json
{"action":"set","protocol":"http","host":"proxy.example.com","port":8080,
 "user":"логин","password":"пароль","noProxy":["localhost","api.deepseek.com"]}
```

Готовая строка тоже принимается: `{"action":"set","proxy":"http://user:password@host:8080"}`.

## Выбор адреса по пингу

Список кандидатов удобно держать в конфиге записи плагина — тогда их не нужно
перечислять в каждом вызове. **По умолчанию там пусто: прокси не вписан и не включён.**

```yaml
- id: rus-image-percent-gen
  name: 'rus-image-percent-gen'
  config:
    proxy:
      enabled: true
      url: 'http://user:password@proxy-a.example.com:8080'   # включается при запуске
      candidates:                                            # что проверять
        - { name: 'Домашний', protocol: http, host: proxy-a.example.com, port: 8080, user: u, password: p }
        - 'http://user:password@proxy-b.example.com:8080'
      noProxy: ['localhost', '127.0.0.1']
      exportEnv: true
```

```json
{"action":"check"}
{"action":"check","choose":true}
{"action":"check","proxies":["http://10.0.0.5:3128"],"timeout_ms":2000}
```

Замер честный: запрос идёт **через сам прокси**, поэтому время — это полный круг до
сайта, а не «пинг до порта». Мёртвый адрес отсекается по отказу соединения или таймауту,
живой показывает внешний IP — видно, что трафик действительно ушёл через него.

## Пример полного прохода

```json
{"action":"status"}
{"action":"check","choose":true}
{"action":"status"}
{"action":"off"}
```

## Правила и ограничения

- **Поддерживаются HTTP(S) и SOCKS5.** У SOCKS5 нет своего списка обхода: `noProxy` к нему не применяется.
- **Логин и пароль в ответах скрываются** (`http://***@host:8080`), но сам адрес
  лежит в аргументе вызова — если он секретный, не пересказывай его в чате.
- **Живой прокси ещё не значит рабочий для модели.** `check` проверяет доставку
  запроса и внешний адрес; попадёт ли конкретный сервис под блокировку самого
  прокси — видно только настоящим запросом к модели.
- **Внутрипроцессный прокси ставится через `undici`.** Если пакет не установлен
  рядом с плагином, `set`/`env`/`check` честно скажут об этом — тогда либо поставь
  `undici`, либо используй отдельный плагин прокси с карточкой настроек.
- **Не запускай два механизма сразу.** Если в профиле уже есть плагин прокси
  (например `@memef1f1y/dsh-plugin-proxy`), держи включённым только один: оба пишут
  один и тот же глобальный диспетчер.
- **У прокси есть кнопка-переключатель в подвале панели и отдельная страница настроек** (Настройки → Прокси): части адреса,
  включение-выключение, проверка кандидатов по пингу со страной. Настройки со страницы лежат
  в файле `$DSH_HOME/rus-image-percent-gen.json` и, если он есть, применяются при запуске вместо
  `proxy.url` из конфига записи.
- Управление живёт до перезапуска DSH. Чтобы адрес задавался сам при запуске,
  впиши его в конфиг записи плагина (`cordis.patch.yml`, поле `proxy.url`) —
  пример есть в README.
